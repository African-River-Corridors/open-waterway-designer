- **The river mouth, where chainage 0 is (spec 0017, the rest of ticket 4, #522).** `owd import --mouth downstream` takes the lower end of the river, by the water level or the DEM; `owd import --mouth LON,LAT` takes the end nearer to a point. The web app has the same field ("River mouth"), and both call one shell function, so they give the same document. When the mouth is the far end of the stored centreline, the river is turned once: the centreline and banks are stored running from the mouth, and the water level, the bed depths, the waterway reaches and the low-confidence stretches are counted from it; a stored reference line is removed, to be made again. The mouth is kept as the point it resolved to (`inputs.mouth`), so a later import keeps the same orientation, and left and right still name the banks looking downstream. `downstream` with neither a water level nor a DEM is refused with `RIVER_MOUTH_UNKNOWN`. A design with no mouth, and every file from an older format, keeps its lines and chainages as they were.
