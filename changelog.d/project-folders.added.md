- **Standard project folders (PROJ-1).** A project folder holds one study in one place: `owd-project.json` (a small text file that says what is there), `design/<name>.owd`, `terrain/<name>.tif`, `inputs/` and `exports/`. The text file names the design, the DEM and the source data (centreline, river polygon, bank lines, water levels by pool) by paths from the folder, with forward slashes; an absolute path and a path that leaves the folder (`..`) are refused; every key but `owd_project` is optional; a key OWD does not know is kept when the file is written again. One typed model reads, checks and writes it for the web app and the command line (`owd_format::project`), with refusals in plain words. **Web app:** **Open project** in the toolbar asks for the folder (Chrome and Edge), reads the text file, opens the design and loads the DEM in one step, with a progress line for the DEM read. Save then writes back to the design file in the folder, and Export GeoJSON, Export CSV, the sheet PDFs and the reports go into `exports/`, with one notice saying where. A folder with no text file shows what OWD found in the standard places and offers "Use these and write owd-project.json"; with more than one design or DEM the user picks. A **Project** panel above Data lists each item as loaded, found and not loaded, or missing, with a Load button for an input that is in the folder but not in the design. The folder is remembered on this machine (IndexedDB) and offered as "Reopen *title*" at the next start. Firefox and Safari have no folder dialog: the button says so, and Open and Load… stay. Nothing is uploaded, and no folder name or path goes into the design file or an export. **Command line:** `owd project init <folder> [--title T]` makes the folders and the text file (it never overwrites one); `owd project status <folder>` lists what is named and whether each file is there, and checks the DEM against the hash the design recorded; every command that takes a design file takes a project folder in its place. The design still names its DEM from its own folder (`../terrain/x.tif` in a project): `init` and Open project point a design at the project's DEM when it is the same file under another path. See `docs/project-folder.md`.
