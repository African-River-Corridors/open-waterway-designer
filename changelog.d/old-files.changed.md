- **A design saved in format 0.4 is turned to run from the river mouth when it opens (spec 0017).** A 0.4 file records no mouth, so OWD works it out: the end with the lower water level, else, with no water level that can tell, the lower end of the DEM when the command line or the app has loaded it beside the file. When the mouth is the far end, the river inputs are turned as `owd import --mouth` turns them, and so are the stored results of every stage: the design lines, the optimise stage's baseline, pools, water profile and weirs, and the volumes' constraint stretches and warnings. A stage that was fresh stays fresh. When the mouth is already the first end it is recorded and nothing else changes. When neither the water level nor the DEM can tell, the file is not turned and a note says to state the mouth. Opening the saved file again turns nothing.
